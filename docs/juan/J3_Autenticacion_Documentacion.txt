3. CÓMO FUNCIONA CADA FLUJO
----------------------------------------------------------------------
REGISTRO (POST /crear-usuario, registro.guardar)
  1. RegistroRequest valida: nombre (máx. 100), identificacion (5-15 dígitos, única), correo (válido,
     único, se guarda en minúsculas), password (mín. 8, con confirmación), tipo_cuenta (estandar o
     familiar) y consentimiento (obligatorio).
  2. El controlador traduce identificacion -> users.cedula y correo -> users.email.
  3. rol = tipo_cuenta, activo = true, consentimiento_datos_at = ahora. Se asignan a mano porque rol y
     activo NO son asignables en masa.
  4. La contraseña se guarda con hash (el modelo User la declara con cast 'hashed').
  5. Se inicia sesión, se regenera la sesión y se va al panel con "Registro exitoso".
  Errores: "Este correo ya se encuentra registrado", cédula repetida, contraseña corta, etc.; se
  conservan los datos escritos menos la contraseña.

LOGIN (POST /iniciar-sesion, login.entrar)
  1. LoginRequest intenta Auth::attempt con email + password.
  2. Falla -> "Usuario o contraseña incorrectos" (igual si el correo no existe).
  3. Acierta pero users.activo = false -> se cierra y avisa "Tu cuenta está suspendida...".
  4. 5 fallos en un minuto para el mismo correo + IP -> bloqueo con "Demasiados intentos fallidos.
     Intenta de nuevo en N segundos." (aunque la contraseña sea correcta). Un acierto reinicia la cuenta.
  5. Éxito: se regenera la sesión. Destino: administrador -> admin.estadisticas; los demás -> panel;
     si venía de una URL protegida, vuelve a ella.

LOGOUT (POST /cerrar-sesion, logout): cierra sesión, invalida la sesión, regenera el token, va a inicio.

RECUPERAR CONTRASEÑA
  1. POST /recuperar-contrasena (password.email, máx. 5 por minuto): siempre responde
     "Si el correo está registrado, te enviamos un enlace...", exista o no.
  2. El enlace (password.reset) apunta a /restablecer-contrasena/{token}. En desarrollo no sale por
     correo: se busca en storage/logs/laravel.log.
  3. POST /restablecer-contrasena (password.update): si el token es válido cambia la contraseña y va
     al login con un aviso. Token reutilizado, vencido o falso -> "El enlace no es válido o ya venció".

----------------------------------------------------------------------

  2. /crear-usuario: registra a alguien nuevo (tarjeta estándar y luego familiar). Debe llegar al panel.
  3. Cierra sesión. Entra con una contraseña mala: mensaje genérico. Hazlo 6 veces: mensaje de espera.
  4. Entra con admin@test.com: debe ir a /admin/estadisticas.
  5. /recuperar-contrasena: escribe un correo, busca el enlace en storage/logs/laravel.log, ábrelo,
     cambia la contraseña y entra con la nueva. Abre el mismo enlace otra vez: debe fallar.
  6. Cerrada la sesión, abre /gastos: debe llevar al login, y al entrar volver a /gastos.
  Pruebas automáticas: php artisan test --filter=AuthTest   (o php artisan test para todas).
