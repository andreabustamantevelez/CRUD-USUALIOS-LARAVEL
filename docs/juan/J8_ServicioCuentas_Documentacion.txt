3. CONTRATO C7 - FIRMA Y COMPORTAMIENTO
----------------------------------------------------------------------
  ServicioCuentas::cambiarTipo(User $usuario, string $nuevoTipo): void
      (ya existía desde J5; sin cambios)

  ServicioCuentas::eliminarCuenta(User $usuario): void            <- NUEVO
      1. Verifica que no sea el último administrador activo.
         Si lo es, lanza ValidationException:
           "No puedes eliminar tu cuenta porque eres el único administrador activo del sistema."
      2. Cancela las metas compartidas activas donde el usuario es creador o participante
         aceptado; avisa al otro participante con notificación TIPO_META_ABANDONADA.
      3. Borra el usuario. La FK en cascada limpia gastos, gastos fijos, pagos,
         simulaciones, informes, detalles, metas creadas, participaciones, aportes y
         notificaciones.
      Todo dentro de DB::transaction.

4. DETALLE DEL FLUJO DE METAS COMPARTIDAS (DECISIÓN #18)
----------------------------------------------------------------------
  Cuando $usuario se va:

  1. Busca metas compartidas en estado activa donde:
        - $usuario es creador, o
        - $usuario es participante con estado_invitacion = 'aceptada'.

  2. Por cada meta:

     a) Si $usuario es el creador:
           - Toma al primer otro participante aceptado.
           - Si no hay ninguno: continue (la FK CASCADE se llevará la meta; no hay a quién
             avisar).
           - Si hay: transfiere metas.creador_id a ese participante. La meta sobrevive.

     b) Marca la meta como estado = 'cancelada'.

     c) Por cada otro participante aceptado:
           - Crea notificación TIPO_META_ABANDONADA con el mensaje:
             "La meta compartida "{nombre}" se canceló porque el otro participante eliminó
              su cuenta."
           - clave_unica = "meta_abandonada:{meta_id}:{user_id}" (idempotente).

  Nota: los aportes y participaciones históricas se conservan por parte del otro
  participante. Al borrar al usuario, sus propias participaciones y aportes sí se borran
  por cascade, pero la meta y los datos del otro quedan.


----------------------------------------------------------------------
5. POR QUÉ TRANSFERIR CREADOR_ID (BUG ENCONTRADO Y CORREGIDO)
----------------------------------------------------------------------
  La tabla metas.creador_id es una FK a users.id con ON DELETE CASCADE (J2). Al borrar al
  creador, la BD elimina la meta automáticamente, aunque antes la hayamos marcado como
  cancelada. El primer test falló con "Attempt to read property 'estado' on null".

  Solución: antes de borrar al usuario, si es el creador de una meta compartida activa,
  se le asigna el creador_id al otro participante aceptado. Así la meta sobrevive y el otro
  ve su historial de aportes, como pedía la decisión #18.

6. LO QUE VALERIA (V4) TIENE QUE HACER EN SU CONTROLADOR
----------------------------------------------------------------------
  public function destroy(Request $request)
  {
      $request->validate([
          'password' => ['required', 'current_password'],
      ]);

      $usuario = $request->user();

      try {
          app(\App\Services\ServicioCuentas::class)->eliminarCuenta($usuario);
      } catch (\Illuminate\Validation\ValidationException $e) {
          return back()->withErrors($e->errors());
      }

      auth()->logout();
      $request->session()->invalidate();
      $request->session()->regenerateToken();

      return redirect()->route('inicio')
          ->with('exito', 'Tu cuenta se eliminó correctamente.');
  }

  Regla: NO cerrar la sesión antes de llamar al servicio (se necesita $request->user()).
  Y capturar ValidationException para mostrar el mensaje al usuario (último admin activo).
